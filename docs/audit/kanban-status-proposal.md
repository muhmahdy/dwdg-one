## How the proposal was decided

| Status | Rule used |
|---|---|
| done | Every acceptance point is visibly implemented **and** a passing vitest test or a documented parity/QA check covers it. The card also needs evidence text (the planner refuses done without it). |
| review | The React app (demo mode) implements the card's acceptance points, but no test or documented check covers them; or the check is a parity comparison with the prototype only. |
| doing | Part of the acceptance is built; the rest needs something that does not exist yet (a live Supabase project, a server rule, an unwritten feature). |
| backlog | Needs things that do not exist: a policy document, an owner decision, hosting, CI, production data, a pilot. |

## Notes and limits of this review

- Judged from reading code, the audit documents, test files and the passing test run. The app was not opened in a browser for this review and no acceptance number (px sizes, contrast) was re-measured.
- A card moved to review or doing does not mean the PRD acceptance is met; it records that work exists. Dependencies in `dependsOn` were not enforced: for example C019 is proposed as review although C002 (policy) is still backlog, because the screens exist.
- Evidence for the cards that stay review (C010, C011, C015 to C018) comes from the prototype sessions of 6 Oct 2026. The React app re-implements those screens with parity checks, not with fresh PRD measurements.
- The workspace is still being edited by another session (Finance fixes). `finance.test.ts` and several `fnl` files were uncommitted when this was written, so C057 and C058 evidence may shift.
- Evidence text proposed for the planner should be shortened to what a reviewer needs; the Evidence column here is longer than the card field needs to be.

## How to apply after approval (not run)

```powershell
# 1. Read the current etag (revision 16 unless someone saved since)
node .planning/dwdg-one-prd/planner-cli.mjs show > C:/tmp/ws-show.json
# take "etag" from that file; also resolve each card's array index by id

# 2. Write operations.json: for every card, guard with a test on the id, then replace status and evidence
# [
#   { "op": "test",    "path": "/cards/<index>/id",       "value": "C013" },
#   { "op": "replace", "path": "/cards/<index>/status",   "value": "review" },
#   { "op": "replace", "path": "/cards/<index>/evidence", "value": "2026-10-17: <short evidence from this table>" }
# ]

# 3. Validate the working copy, then apply with the etag, an actor label and a summary
node .planning/dwdg-one-prd/planner-cli.mjs patch C:/tmp/operations.json --base <ETAG_FROM_SHOW> --actor "Claude (status review)" --summary "Kanban status review against React code, 2026-10-17, see docs/audit/kanban-status-proposal.md"

# 4. Confirm
node .planning/dwdg-one-prd/planner-cli.mjs check
```

The CLI writes a backup to `state/backups/`, appends to the saved history and rejects a stale etag. If the owner approves only some rows, include only those cards in `operations.json`.
