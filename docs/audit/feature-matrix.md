# Feature matrix

Every feature of the app, mapped to its PRD references, its React implementation (`frontend/src/`) and its migration and test status. The feature list was first taken from the prototype inventory (`frontend/prototype/`), so each row also names the prototype file it came from. That column is history for tracing, not the place to look for current behaviour: **since 17 Oct 2026 (Phase 3 complete) the React app is the implementation of record.** What the prototype still has that React lacks is listed in `prototype-gap.md`; the prototype stays in the repository until that file lists nothing and Phase 6 archives it (decisions M16 and M22).

- **Counts** come from `docs/audit/prototype-registry.json`, a frozen inventory of the prototype (it is not regenerated as React changes). `scripts/qa/inventory-prototype.mjs` loads the 21 scripts in `index.html` order inside happy-dom and records which file registers each entry. Totals: **39 pages, 56 inspector panels, 38 menus, 542 actions, 39 input handlers, 38 change handlers**, 7 capability groups. These totals match the earlier measurement in `next-app/AUDIT.md`.
- **PRD references** are the node ids cited in that file's source (`docs/audit/prd-citations.json`). Requirement-level tracing is in `traceability-matrix.md`.
- **"L"** marks pages in the `LATER` set (D58 "Ship 1"). They are hidden until an Admin turns on Settings → Release preview, but they are still features and are migrated (M17, master prompt §2).
- **Migration status:** Not started / In progress / Migrated / Verified. **Test status:** Baseline = screenshot in `qa/refactor-baseline/{desktop,mobile}/`; Parity = the React screen compared against the baseline; Unit / E2E = automated tests in `frontend/tests/`.

## Looks: Compact and Simple parity (checked 17 Oct 2026)

Each page was captured in the prototype and in the React demo (1440×900, same persona and seed, `scripts/qa/shot.mjs` setup) and compared pixel by pixel. "Mismatch" is the share of pixels that differ by more than a small colour distance; text anti-aliasing alone gives about 0.1 to 0.3 %. Pages that differed were fixed until only sub-pixel noise or a documented difference remained.

| Page | Compact | Simple | What was fixed or what remains |
|---|---|---|---|
| My Work | 0.5 % | 0.1 % | Simple: "Waiting for you" was reusing the Comfortable rail rows. It is now its own list (`features/simple/components/SimpleWaiting.tsx`) with the prototype's order (offers, reviews, shared tasks, meetings, invitations), a **Review** button on offer and review rows, and Decline / Accept on the rest. Compact: rail rows and groups use the prototype's tighter padding and wrap long titles. |
| Projects | 0.4 % | 0.8 % | Compact: group header rule and padding, card number sizes. Simple: status chip row offset. **Remains:** in Simple the prototype's division dropdown stretches across the toolbar because its custom-select wrapper ignores the stylesheet's `max-width: 280px`; React follows the stylesheet (search takes the free width, dropdown at most 280 px). |
| Programs | 0.6 % | 0.2 % | Compact: gap under the header, period chip size, narrow progress bar. |
| Operations | 0.6 % | 0.3 % | Both: Rhythm labels use the larger routine art. Compact: framed Rhythm box, week-row dots between facts, tab spacing. Simple: "Your turn" rows open the task and show the 52 px art and bold title. |
| Attention | 0.3 % | 1.6 % | Row height, title and button sizes per look. |
| Schedule | 3.4 % | 1.0 % | Mini-calendar header and weekday row heights; event padding and time-chip size at narrow column widths. **Remains:** Compact differs by one pixel of calendar scroll position (hour lines), so every line counts as different. |
| Settings | 0.2 % | 0.2 % | Page title offset; Simple account avatar size. |
| Performance, Resources | 0.5 %, 0.4 % | 1.2 %, 0.1 % | No change needed. Simple Performance keeps about 1 % of text anti-aliasing and one-pixel row offsets. |
| Updates | 5.6 % | 4.7 % | **Regressed by an uncommitted edit that was in the working tree before this pass** (`UpdatesPage.tsx`: white cards per day group, wide canvas). The prototype's Compact and Simple pages are flat lists, so the card style should be limited to Comfortable. It measured 0.3 % and 0.1 % before that edit. |
| Shell | | | Active navigation icons use their solid form in Compact and Simple, as in the prototype; Compact role line size. Quick-add and search inputs keep the browser's 2 px input padding like the prototype. |

Not part of this pass: the Comfortable look. Its Projects, Programs, Operations and Attention pages still show 4 to 8 % mismatch (mostly 1 to 3 px vertical offsets); they are listed in `prototype-gap.md`.
