# Resources keyboard and enlarged-text verification

Verified 4 October 2026. This is a bounded pass on the separate DWDG’ONE preview's Resources flow. The full UI/UX goal and the working-draft PRD remain incomplete.

## Changes

The closed mobile drawer is now excluded from keyboard navigation. Choosing a page focuses its visible heading. Resources inspector entry focuses Back/Close, and returning restores the actual title/More opener after its saved scroll. Saved-note references return to the same occurrence, including two references to one resource. Save, Cancel, editor Escape, related subforms and Undo select a remaining control instead of leaving focus on the document body. A scoped focus check reveals fields and disclosure controls only when the toolbar, sticky actions or viewport would cover them.

The shared overlay controller now restores focus when the outgoing layer becomes inert, before resolving a confirmation. Its exit callback only removes that layer. This fixes both the temporary body-focus gap and a delayed callback stealing focus from a newly opened editor. The existing 200/300ms animation waits, replacement/nested ownership, busy guards and destroy cleanup remain covered by regressions. **This small shared focus correction also applies to the preserved app**; the original app's bundle therefore changed. Its stores, records, attachments, backups and PRD editor were not migrated or reset.

Preview styles allow navigation, responsibility and selected-control text to grow. The ordinary desktop sidebar remains 216px; the doubled-text simulation grows it to 432px. Dialog Close retains a 44px target even beside a wrapping title. In windows at most 480px tall, form actions flow normally and the note field can fit beneath the shell. At 320×225 its measured height is 113px; native Tab reveals the entire field and the actions. The ordinary note-editor measurements at normal phone heights remain unchanged.

## Fixture and limits

[The fixture](fixture.html) imports production preview/domain modules and uses only an in-memory adapter. Six resources per current division include folders, notes, provider links, long titles and one canonical illustrative related task. Reload deliberately recreates these disposable IDs; this fixture **does not** demonstrate browser-storage persistence. The existing isolated rehydration tests and earlier [notes browser save/reload verification](../dwdg-one-notes/VERIFICATION.md) retain that separate evidence. The user's preview records and preferences were not changed by this pass.

The temporary fixture tab was closed and the viewport override reset. The user's existing Resources preview remains open in its original language/theme/workspace, with its existing records intact; [the final normal-window view](user-preview-final.jpg) records that context.

The typography helper doubles source-declared pixel font sizes/line heights while preserving media/container rules. Spacing overrides apply together: line height 1.5, letters 0.12em, words 0.16em and paragraph bottom margin 2em. They are QA user styles, **not browser-native text resizing**. The 320×225 viewport represents the CSS space of 1280×900 at 400% zoom, **not native 400% browser zoom certification**. Native zoom/text resizing, real mobile keyboards/devices, screen readers, every action's contrast and the full page/role matrix remain unverified.

Default compact density remains readable. Enlarged 320px states grow substantially and some long words break within a word; the compact shell context ellipsizes while page/content text remains available. Initial screenshots do not show every lower control; the separate keyboard traces establish the visited controls only. [Before captures/traces](before-editor-keyboard.json), `initial-interactions.json` and `animation-sampling.json` are diagnostics, not passed evidence. The earlier body-focus failures were retested after the overlay correction and are excluded from the final 40-observation set.

No backend, provider-content integration or native binary upload was added. PRD decision statuses, budgets, organization draft and production Changes requirement remain unchanged. Schedule/availability, other unfinished pages, specialist division workflows and role/device acceptance still require further iterations.
