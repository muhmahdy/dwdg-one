# Roadmap — one whole-app delivery

## Phase 01 · Reference-led redesign

**Goal:** every page embodies the approved references while existing local workflows and records keep working. [Execution plan](phases/01-reference-redesign/01-PLAN.md).

| Internal wave | Work | Gate |
|---|---|---|
| 1 | Read active sources, inspect references, preserve source, agree shared tokens and density; update specification | Approved directions are concrete; source backup exists |
| 2 | In parallel: shell/core working pages and shared charts; six division layouts; secondary pages; documentation and acceptance | All routes use the same visual contract and retain functional actions |
| 3 | Integrate style ownership, run existing tests/startup checks/build, repair failures | Automated checks pass and no known regression remains |
| 4 | Inspect actual settled rendering; exercise reference journeys; fix findings; collect evidence | Current acceptance criteria have actual evidence or explicitly stated blockers |

These are internal implementation waves, not staged user approvals. Continue through all pages before handoff. No backend phase, framework migration, data reset, or new integration belongs to this delivery.

Phase status remains **in progress** until the current [verification report](../qa/reference-redesign/VERIFICATION.md) establishes the result. A blocked browser check remains unverified; a build pass cannot close that gate.
