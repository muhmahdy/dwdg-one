## Requirements this stream owns (2)

### Browser AI agents act through WebMCP tools with the member’s own permissions
`integration-webmcp` · confirmed · P1 · parent `integrations` · owner: Product + engineering owners

Owner requirement D25 (6 Oct 2026): DWDG’ONE exposes its actions to the member’s own browser AI agent through WebMCP (the W3C Web Machine Learning community draft, navigator.modelContext; the architecture record verifies the current spec and browser support before building). The page registers tools with a name, description and input schema; the agent calls them inside the signed-in member’s session, so every tool runs the same server permission, consent and version checks as the visible UI and can do nothing the member could not do by hand. Proposed first tool set: read my work (tasks by section, offers, reviews), read my schedule and find shared free time (busy/unknown only, never private notes or Google titles), search permitted records, create or update my own task, set task status, raise a blocker, draft a task offer, draft a meeting. Any tool that affects other people (send an offer, send meeting invitations, approve, record a decision) needs an explicit confirmation by the human in the page before it commits. Changes and Updates label agent-made changes as made through a browser agent on the member’s behalf. No AI backend, model API key or paid service is required (integration-ai stays deferred); the app works identically when the browser has no WebMCP support. Tool names, descriptions and results follow the member’s language.

**Acceptance:**
1. With WebMCP available, an agent lists only the tools for actions the signed-in member is permitted to take; a Member sees no project-creation tool.
2. A tool call is rejected by the server whenever the same action would be denied in the UI (0 permission bypasses in the denial fixtures).
3. Sending an offer or meeting invitation through a tool commits only after the member confirms in the page; declining the confirmation commits 0 changes.
4. Agent-made changes appear in Changes with the member as actor and a browser-agent label.
5. Tool results contain 0 private unavailable-time notes, Google event titles, HR fields or secrets.
6. Without WebMCP support the app shows no errors and loses no function.

**Prerequisites:** `security_permissions`, `engineering-api` (ARC), `data_commands` (WRK), `work_forms` (UX1), `access_delegation` (WRK)
